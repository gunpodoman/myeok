# 면접-평가 핸드오프 규격 v1.1 FINAL

## 0. 문서의 역할

이 문서는 面逆力 웹사이트와 평가 엔진 사이의 공식 데이터 계약인 `INTERVIEW_EVAL_HANDOFF/1.1`의 사람이 읽는 최종 명세다.

전체 흐름:

```text
INTERVIEW_PACK/1.0
→ 面逆力 웹사이트에서 실제 면접 진행
→ INTERVIEW_EVAL_HANDOFF/1.1
→ 평가 엔진
```

질문 생성 엔진은 HANDOFF를 직접 생성하지 않는다.

HANDOFF 생성 주체:

```text
面逆力 웹사이트
```

핵심 철학:

> 사이트는 기록한다.

> 평가 엔진은 해석한다.

> handoff.json이 canonical source다.

> HANDOFF는 평가 결과가 아니라 관찰 기록이다.

> null과 0을 구분한다.

> 질문 Intent를 사후 수정하지 않는다.

> STT 원문을 임의 복원하지 않는다.

> Runtime Signal은 평가 정답이 아니다.

# 9. source_pack.sha256

알고리즘:

```text
SHA-256
```

대상:

> 사용자가 업로드한 원본 `interview-pack.json` 파일의 원본 byte sequence.

금지:

- JSON parse 후 재직렬화한 결과를 hash
- 정규화된 JSON을 hash
- pack_id를 hash처럼 사용

표현:

```text
64자리 lowercase hexadecimal
```

목적:

- 원본 Pack 동일성 확인
- 디버깅
- 세션 재현
- pack_id 충돌 보조 방지

hash를 개인정보 보호·전자서명 기능으로 과장하지 않는다.

# 26. 실제 제시 문구 question_text

# 40. speech_ratio / silence_ratio

둘 다 측정된 경우:

```text
0.0 <= value <= 1.0
```

일반적으로:

```text
speech_ratio + silence_ratio ≈ 1
```

작은 floating point 오차는 epsilon 허용.

한 값이 미수집이면 null.

나머지 값을 임의로 계산하여 채우지 않는다.

# 47. runtime_signal의 의미

`runtime_signal`은:

> 해당 질문에 답한 뒤 사이트가 관찰한 규칙 기반 신호.

예:

Q01 답변이 짧아 Q02를 선택했다면:
- Q01.runtime_signal에 ANSWER_TOO_SHORT 관찰 가능
- Q02.followup_trigger에 Q01 신호가 Q02 선택에 사용됐음을 기록

두 필드의 역할을 혼합하지 않는다.

---

# 48. runtime_signal 공통 구조

`runtime_signal`은 `null` 또는 object.

공통 필수:

```text
type
observed
used_for_branching
```

type은 공식 trigger enum.

trigger 종류에 따라 허용 필드가 달라진다.

---

# 49. runtime_signal — ANSWER_TOO_SHORT / LONG

예:

```json
{
  "type": "ANSWER_TOO_SHORT",
  "observed": true,
  "measured_value": 8200,
  "threshold_value": 15000,
  "unit": "ms",
  "used_for_branching": true
}
```

`measured_value`, `threshold_value`는 정수.

unit은 `"ms"`.

---

# 50. runtime_signal — KEYWORD_ANY

```json
{
  "type": "KEYWORD_ANY",
  "observed": true,
  "matched_keyword": "정확도",
  "matched_text": "정확도가 높아졌습니다",
  "used_for_branching": true
}
```

이는 의미판정이 아니라 문자열 감지 사실.

---

# 51. runtime_signal — RANDOM

```json
{
  "type": "RANDOM",
  "observed": true,
  "probability": 0.25,
  "used_for_branching": true
}
```

probability:

```text
0.0 ~ 1.0
```

---

# 52. runtime_signal 의미론적 판정 금지

# 89. 최종 성공 기준

본 규격의 목표는 평가를 사이트에 추가하는 것이 아니다.

성공 기준:

- Pack 질문 메타데이터가 손실되지 않음
- 실제 제시 문구가 보존됨
- trigger 원인이 구조화됨
- 원본 Pack 동일성을 추적 가능
- event timestamp 기준이 명확
- summary coverage가 보존됨
- null과 0을 구분함
- STT 원문과 수정본을 구분함
- audio reference가 추적 가능함
- 모든 enum과 참조가 JSON Schema로 옮길 수 있을 만큼 명확함

최종적으로:

> 사이트의 주관을 끼워 넣지 않고, 실제 면접에서 발생한 질문·답변·환경·시간·STT·발화행동·기술상태를 평가엔진이 독립적으로 해석할 수 있을 정도로 손실 없이 보존한다.

이 문서는 이후 작성될 `INTERVIEW_EVAL_HANDOFF/1.1` JSON Schema의 사람이 읽는 공식 명세 역할을 한다.
